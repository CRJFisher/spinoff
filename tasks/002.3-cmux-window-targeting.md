# Window Targeting & Overview Auto-Switch

When a user runs `/spinoff:new` from inside a cmux tab, new agent tabs should open in the same cmux window — and the overview tab should be ensured and focused automatically.

## The `identify` pattern

cmux injects `CMUX_WORKSPACE_ID` and `CMUX_SURFACE_ID` into every terminal session. The `identify` command uses these to resolve the caller's full context:

```json
{
  "focused": { "window_id": "...", "workspace_id": "...", "pane_id": "...", "surface_id": "..." },
  "caller":  { "window_id": "UUID", "workspace_id": "UUID", "surface_id": "UUID", ... }
}
```

`caller.window_id` tells us which window the calling terminal lives in — even if that window isn't focused. This replaces WezTerm's pattern of iterating all panes and matching by workspace name.

| Concern              | WezTerm (current)                                    | cmux (proposed)                                             |
| -------------------- | ---------------------------------------------------- | ----------------------------------------------------------- |
| Find parent window   | Iterate all panes, match `workspace == project_name` | `cmux identify --json` → `caller.window_id` (one call)      |
| Create tab in window | `wezterm cli spawn --window-id <id>`                 | `cmux --window <id> new-workspace --cwd <path>`             |
| Name the tab         | `set-tab-title --pane-id <id>`                       | `rename-workspace --workspace <id> <title>` (separate call) |
| Focus stealing       | Tab is auto-focused                                  | Tab created in background by default                        |
| Overview auto-switch | Not implemented                                      | `select-workspace --workspace <overview_id>`                |

## Focus behavior

`workspace.create` is NOT in cmux's `focusIntentV2Methods` allowlist. New workspaces are created in the background — the user stays on their current tab. This is confirmed by cmux's regression tests.

`workspace.select` IS in the allowlist. `cmux select-workspace --workspace <id>` switches the visible tab in the sidebar and works from scripts.

This means we can: create the agent tab silently, then switch the user to the overview.

## Workspace discovery

`cmux --json list-workspaces --window <id>` returns per workspace:

```json
{
  "id": "UUID",
  "ref": "workspace:1",
  "title": "my-project",
  "selected": true,
  "current_directory": "/Users/chuck/workspace/my-project",
  "pinned": false,
  "custom_color": null
}
```

Fields available: `title` (user-settable via `rename-workspace`), `current_directory` (detected from shell integration), `id`/`ref` for addressing, `selected` for which workspace is active.

`list-workspaces` is scoped to a single window. There is no cross-window query — you must specify `--window`.

## Workspace ordering

The `workspace.reorder` API supports moving workspaces to specific positions:

```bash
cmux rpc workspace.reorder '{"workspace_id":"<id>","index":0}'
```

The overview workspace can be pinned to position 0 (first in sidebar).

## The flow

```
/spinoff:new fix-auth
    │
    ├─ 1. cmux identify --json
    │     → caller.window_id (which window are we in?)
    │
    ├─ 2. cmux --window <id> new-workspace --cwd <worktree_path>
    │     → creates agent tab in background (no focus steal)
    │
    ├─ 3. cmux rename-workspace --workspace <agent_ws> "myapp: fix-auth"
    │     → name it for sidebar visibility
    │
    ├─ 4. cmux send --workspace <agent_ws> <startup_command>
    │     → launch Claude in the agent tab
    │
    ├─ 5. Find overview workspace:
    │     cmux --json list-workspaces --window <id>
    │     → search for title == "myapp: Overview"
    │     │
    │     ├─ Found → use existing overview_ws
    │     └─ Not found:
    │           cmux --window <id> new-workspace
    │           cmux rename-workspace --workspace <new_id> "myapp: Overview"
    │           cmux rpc workspace.reorder '{"workspace_id":"<id>","index":0}'
    │           cmux send --workspace <new_id> "python -m spinoff.overview watch ..."
    │
    └─ 6. cmux select-workspace --workspace <overview_ws>
          → switch user to overview tab
```

## Naming convention

Workspaces are named `{project_name}: {label}`:

- `myapp: fix-auth` — agent workspace
- `myapp: feat-dark-mode` — agent workspace
- `myapp: Overview` — overview dashboard

This makes the sidebar self-documenting and enables lookup by title prefix.

## State model

`.state.json` gains project-level cmux fields:

```json
{
  "window_id": "cmux-window-uuid",
  "overview_workspace_id": "cmux-workspace-uuid",
  "worktrees": [
    {
      "name": "fix-auth",
      "terminal_id": "cmux-workspace-uuid",
      ...
    }
  ]
}
```

`window_id` is the cmux window for this project. `overview_workspace_id` is the overview tab. Both are verified on each `/spinoff:new` and cleared if stale.

## Edge cases

| Scenario                            | Handling                                                                                                                |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| User closed the cmux window         | `--window <stale_id>` fails → clear from state, re-detect from `identify` or create new window                          |
| Spinoff called from outside cmux    | `identify` returns `caller: null` → check state for stored `window_id`, verify via `list-windows`, or create new window |
| Multiple projects, multiple windows | Each project stores its own `window_id` — no collision                                                                  |
| Overview already exists             | `list-workspaces` finds it by title → `select-workspace`                                                                |
| Overview poller died                | Check PID liveness → restart poller in existing overview workspace                                                      |
| Overview workspace closed by user   | `overview_workspace_id` stale → create fresh on next spinoff                                                            |

## Known cmux gaps

1. **`new-workspace --name` is a no-op.** The CLI flag exists but the server handler doesn't read it. Renaming must be a separate call. Minor inconvenience, not a blocker.
2. **No `CMUX_WINDOW_ID` env var.** Window ID must be resolved via `identify`, not read directly from the environment. One extra subprocess call.
3. **`--window` global flag steals focus.** It calls `window.focus` before dispatching the command. For multi-window setups this may bring the wrong window to the foreground. Workaround: use the raw socket API with `window_id` in params to avoid focus-stealing. Or accept it — spinoff users typically work in one window.
4. **`workspace.reorder` not exposed via CLI.** Must use `cmux rpc workspace.reorder '{...}'`. Works, but slightly awkward.

## Implementation notes

- The `identify` → `window_id` → `--window` pattern replaces WezTerm's `get_project_window_id()` function entirely.
- The overview auto-switch replaces nothing — WezTerm had no equivalent. This is new functionality enabled by cmux's background workspace creation.
- The naming convention (`project: label`) replaces WezTerm's workspace grouping. WezTerm grouped by workspace name at the window level; cmux groups visually by title prefix within a window.
