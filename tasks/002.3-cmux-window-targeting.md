# Window Targeting & Overview Auto-Switch

When a user runs `/spinoff:new` from inside a cmux tab, new agent tabs open in the same cmux window, and the overview tab is ensured and focused automatically.

## Window ID resolution

cmux injects `CMUX_WORKSPACE_ID` and `CMUX_SURFACE_ID` into every terminal session. `cmux identify --json` resolves the caller's full context:

```json
{
  "focused": {
    "window_id": "...",
    "workspace_id": "...",
    "pane_id": "...",
    "surface_id": "..."
  },
  "caller": {
    "window_id": "UUID",
    "workspace_id": "UUID",
    "surface_id": "UUID"
  }
}
```

`caller.window_id` identifies which window the calling terminal lives in — even if that window isn't focused.

The resolution chain in `create.py`:

1. `cmux.get_window_id()` — live detection via `cmux identify`
2. Stored `state.window_id` — fallback for calls from outside cmux
3. `None` — cmux uses its default window (no `--window` flag)

The resolved `window_id` is persisted to `.state.json` so subsequent runs (or runs from outside cmux) can target the same window.

## Focus behavior

`workspace.create` is NOT in cmux's `focusIntentV2Methods` allowlist. New workspaces are created in the background — the user stays on their current tab.

`workspace.select` IS in the allowlist. `cmux select-workspace --workspace <id>` switches the visible tab in the sidebar.

This means: create the agent tab silently, then switch the user to the overview.

## Workspace discovery

`cmux --json list-workspaces --window <id>` returns per workspace:

```json
{
  "id": "UUID",
  "ref": "workspace:1",
  "title": "my-project",
  "selected": true,
  "current_directory": "/Users/chuck/workspace/my-project",
  "pinned": false,
  "custom_color": null
}
```

`list-workspaces` is scoped to a single window. There is no cross-window query — you must specify `--window`.

## The flow

```text
/spinoff:new fix-auth
    │
    ├─ 1. Resolve window_id:
    │     cmux.get_window_id() → state.window_id → None
    │
    ├─ 2. cmux --window <id> new-workspace --cwd <worktree_path>
    │     → creates agent tab in background (no focus steal)
    │
    ├─ 3. cmux rename-workspace --workspace <agent_ws> "myapp: fix-auth"
    │     → name it for sidebar visibility
    │
    ├─ 4. cmux send --workspace <agent_ws> <startup_command>
    │     → launch Claude in the agent tab
    │
    ├─ 5. Persist window_id to .state.json
    │
    ├─ 6. Find overview workspace:
    │     a. Check stored overview_workspace_id → workspace_exists?
    │     b. Title fallback: find_workspace_by_title("{project}: Overview")
    │     c. Not found → create new:
    │           cmux --window <id> new-workspace
    │           cmux rename-workspace → "{project}: Overview"
    │           cmux rpc workspace.reorder → index 0
    │           cmux send → start poller
    │
    └─ 7. cmux select-workspace --workspace <overview_ws>
          → switch user to overview tab
```

## Naming convention

Workspaces use `{project_name}: {label}`:

- `myapp: fix-auth` — agent workspace
- `myapp: feat-dark-mode` — agent workspace
- `myapp: Overview` — overview dashboard

This makes the sidebar self-documenting and enables lookup by title prefix.

## State model

`.state.json` stores project-level cmux fields:

```json
{
  "window_id": "cmux-window-uuid",
  "overview": {
    "workspace_id": "cmux-workspace-uuid",
    "surface_id": "cmux-workspace-uuid"
  },
  "worktrees": [
    {
      "name": "fix-auth",
      "terminal_id": "cmux-workspace-uuid",
      ...
    }
  ]
}
```

`window_id` is persisted on first resolution and reused for subsequent runs. `overview.workspace_id` tracks the overview tab. Both are verified on each `/spinoff:new` and recovered if stale.

## Edge cases

| Scenario                            | Handling                                                                                        |
| ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| User closed the cmux window         | `--window <stale_id>` fails → next run from cmux re-detects via `identify` and overwrites state |
| Spinoff called from outside cmux    | `identify` returns `caller: null` → falls back to stored `state.window_id`                      |
| Multiple projects, multiple windows | Each project stores its own `window_id` — no collision                                          |
| Overview already exists             | `workspace_exists` finds it → `select-workspace`                                                |
| Overview workspace closed by user   | Stored ID stale → title fallback → create fresh                                                 |
| Overview manually renamed           | Title fallback won't find it → new overview created, old one orphaned                           |

## Known cmux gaps

1. **`new-workspace --name` is a no-op.** The CLI flag exists but the server handler doesn't read it. Renaming is a separate call.
2. **No `CMUX_WINDOW_ID` env var.** Window ID must be resolved via `identify`, not read directly from the environment. One extra subprocess call.
3. **`--window` global flag steals focus.** It calls `window.focus` before dispatching the command. Workaround: accept it — spinoff users typically work in one window.
4. **`workspace.reorder` not exposed via CLI.** Must use `cmux rpc workspace.reorder '{...}'`.
